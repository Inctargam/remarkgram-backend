# Итерация 1: разовая оплата через Stripe Checkout

## Цель итерации

Реализовать минимальный законченный процесс оплаты перед добавлением подписок: создать платёж в локальной системе, перенаправить пользователя на размещённую платёжную страницу Stripe Checkout, принять аутентифицированный вебхук и предоставить сохранённый статус.

## Процесс

Подробная машина состояний и sequence diagram: [Машина состояний платежа](payment-status-state-machine.md).

1. `POST /api/v1/payments/checkout` получает данные аутентифицированного пользователя, `planId` и UUID v4 в заголовке `Idempotency-Key`.
2. Сервис Payments копирует цену, валюту и период из выбранного серверного тарифного плана в платёж со статусом `CREATED`.
3. Сессия Stripe Checkout создаётся вне транзакции базы данных с тем же ключом идемпотентности и внутренним `paymentId` в метаданных.
4. Идентификаторы сессии Checkout сохраняются, а платёж переходит в статус `PENDING`.
5. Stripe отправляет POST-запрос на `POST /payments/webhooks/stripe` через HTTP-порт сервиса Payments. Этот маршрут намеренно не использует API Gateway.
6. Адаптер проверяет `Stripe-Signature` по необработанным байтам запроса.
7. Уникальная запись о событии провайдера и изменение состояния платежа фиксируются в одной транзакции базы данных.
8. `GET /api/v1/payments/{paymentId}/status` возвращает платёж, только если он принадлежит текущему пользователю.

## Намеренные ограничения

- Checkout использует `mode=payment` и поддерживает только оплату картой.
- D2, регулярные платежи, PayPal, возвраты средств, споры и сверка отложены на следующие итерации.
- URL-адреса перенаправления служат только для отображения интерфейса и не могут изменять состояние платежа.
- При тайм-ауте провайдера локальный платёж остаётся в статусе `CREATED`; повторный запрос с тем же ключом возобновляет операцию.
- Несоответствие суммы, валюты или идентификатора Checkout сохраняется в событии провайдера и ни при каких условиях не подтверждает платёж.

## Локальная настройка

Создайте и настройте `apps/payments/.env` на основе `.env.example`, выполните миграцию сервиса Payments, добавьте начальные данные тарифных планов и настройте перенаправление событий Stripe CLI на `http://localhost:3004/payments/webhooks/stripe`. Используйте секрет подписи вебхука, выведенный Stripe CLI.

Готовая Postman-коллекция и локальное окружение находятся в каталоге [`postman`](postman/README.md).
