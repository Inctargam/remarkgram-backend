# План развития архитектуры платежей

Сервис Payments (D1) отвечает за взаимодействие с платёжным провайдером, достоверное состояние платежей и финансовую историю. Сервис Subscriptions (D2) отвечает за периоды действия прав и доступ к бизнес-функциям. Перенаправление в браузере никогда не является подтверждением оплаты; окончательно подтвердить её может только проверенное событие провайдера или результат сверки.

## Итерации

1. Разовая оплата через размещённую страницу Stripe Checkout, подписанные вебхуки и статус платежа.
2. Транзакционный контракт между D1 и D2, который активирует один оплаченный период и сохраняет `subscriptionId`.
3. Режим подписки Stripe и один неизменяемый платёж за продление для каждого оплаченного счёта.
4. Сверка, ограниченные повторные попытки, операционные очереди и метрики.
5. Финансовая история с пагинацией, снимки данных, возвраты средств и споры — по мере необходимости.
6. Отмена автоматического продления по инициативе D2.
7. Адаптер PayPal за портом платёжного провайдера.

## Стабильные границы ответственности

- Клиенты передают только `planId`; цена, валюта и идентификатор пользователя определяются сервером.
- Вызовы платёжного провайдера никогда не выполняются внутри транзакций базы данных.
- Вебхуки провайдера аутентифицируются, дедуплицируются и обрабатываются транзакционно.
- Состояние платежа хранится отдельно от состояния подписки и прав доступа.
- Данные в формате конкретного провайдера остаются внутри инфраструктурных адаптеров.
